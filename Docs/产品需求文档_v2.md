## 1. 引言

### 1.1 背景
随着信息爆炸时代的到来，用户面临海量新闻资讯却难以快速获取准确、相关信息的挑战。传统的关键词搜索已无法满足用户对智能化、个性化信息检索的需求。基于检索增强生成（RAG）技术的智能新闻问答系统应运而生，旨在通过AI技术提升用户的信息获取体验。

### 1.2 目标用户
- **主要用户**：新闻从业者、研究人员、学生、对时事关注度高的专业人士
- **次要用户**：企业分析师、政策研究者、媒体工作者
- **用户特征**：
  - 需要快速获取精准信息
  - 具备一定的数字化工具使用能力
  - 对信息的准确性和时效性要求较高
  - 希望获得结构化、易理解的答案

### 1.3 产品愿景
构建一个基于AI技术的智能新闻知识库系统，通过自动化数据采集、智能语义检索和大语言模型问答，为用户提供精准、高效、个性化的新闻信息服务，成为用户获取新闻资讯的首选AI助手。

## 2. 用户故事与场景描述

### 2.1 核心用户故事

**用户故事1：智能新闻问答**
- **作为**一名新闻记者
- **我希望**能够快速查询特定事件的相关报道和背景信息
- **以便于**我能够在短时间内了解事件全貌，提高报道质量

**用户故事2：知识库管理**
- **作为**系统管理员
- **我希望**能够管理新闻数据源，监控数据质量
- **以便于**确保系统提供准确、及时的信息服务

**用户故事3：个性化信息获取**
- **作为**研究人员
- **我希望**能够上传自己的文档并与新闻库结合查询
- **以便于**获得更全面、个性化的研究支持

### 2.2 典型使用场景

**场景1：突发新闻快速了解**
1. 用户听说某重大事件发生
2. 在系统中输入相关问题（如"今天的地震情况如何？"）
3. 系统检索相关新闻并调用AI生成综合回答
4. 用户获得包含时间、地点、影响等关键信息的结构化答案

**场景2：历史事件深度研究**
1. 用户需要了解某历史事件的发展脉络
2. 输入复杂查询（如"过去一年中美贸易摩擦的发展历程"）
3. 系统检索时间跨度内的相关报道
4. AI整合信息生成时间线式的详细分析

**场景3：个人文档结合查询**
1. 用户上传研究文档或报告
2. 提出结合个人文档和新闻库的查询
3. 系统同时检索个人文档和新闻库内容
4. 生成综合性、个性化的回答

## 3. 产品范围与功能列表

### 3.1 核心功能（MVP）

#### 3.1.1 用户认证系统
- 用户注册/登录功能
- JWT Token认证机制
- 密码安全管理
- 权限控制系统

#### 3.1.2 数据采集系统
- **RSS订阅源管理**
  - 支持添加/编辑/删除RSS源
  - 定时任务机制（APScheduler）自动抓取
  - RSS源分类管理（新闻、财经、科技等）
  - 数据清洗和格式化
- **网页爬虫功能**
  - 支持主流新闻网站内容抓取
  - 遵守robots.txt和爬虫规范
  - 反爬虫策略和频率控制
  - 内容提取和结构化处理
- **智能代理工具**
  - 支持代理IP池管理
  - 自动重试机制

#### 3.1.3 知识库管理
- **数据展示与管理**
  - 知识库内容列表展示
  - 支持按时间、类型、来源筛选
  - 支持单条/批量删除操作
  - 元数据编辑（标签、来源等）
- **文件上传功能**
  - 支持MD、PDF、TXT、DOC、DOCX、RTF格式
  - 自动文本提取和分块处理
  - 文档向量化和自动入库
- **入库通知功能**
  - 数据成功入库后自动发送邮件通知
  - 邮件包含标题、内容预览、入库时间
  - 异步发送，不影响主流程性能

#### 3.1.4 智能检索与问答
- **语义检索引擎**
  - 基于FAISS的向量相似度检索
  - 支持自然语言查询
  - 检索结果重排优化
  - 搜索历史记录和建议
- **AI问答系统**
  - 集成大语言模型（Qwen3:8b via Ollama）
  - RAG（检索增强生成）技术
  - 流式输出支持
  - 多轮对话能力
  - 答案质量评估
- **联网搜索回退**
  - 当本地知识库无结果时自动触发联网查询
  - 集成百度搜索API，返回前3条结果
  - LLM对网络搜索结果进行推理整合
  - 明确标注信息来源（本地知识库/网络搜索）

#### 3.1.5 数据分析与可视化
- **聚类分析功能**
  - 知识库内容自动聚类（KMeans算法）
  - 关键词提取和Top10关键词分布展示
  - 数据分布可视化图表
  - 聚类分析报告生成和导出
- **统计分析功能**
  - 知识库内容统计（总量、分类、来源）
  - 用户搜索行为分析
  - 热点话题识别和趋势分析
- **可视化展示**
  - Top10关键词柱状图/词云图
  - 聚类分布饼图
  - 搜索历史和效果统计图表

### 3.2 高级功能（后续版本）

#### 3.2.1 个性化推荐
- 基于用户搜索历史的内容推荐
- 用户兴趣画像构建
- 主动信息推送

#### 3.2.2 多模态支持
- 图片内容识别和检索
- 视频内容转文字分析
- 音频新闻处理

#### 3.2.3 协作功能
- 多用户协作和分享
- 知识库订阅和同步
- 团队协作空间

## 4. 产品特定AI需求

### 4.1 模型需求

#### 4.1.1 文本嵌入模型
- **模型选择**：sentence-transformers/all-MiniLM-L6-v2
- **功能要求**：
  - 支持中英文文本向量化
  - 向量维度：384维
  - 处理速度：≥1000条文本/秒
- **性能指标**：
  - 语义相似度准确率：≥85%
  - 响应时间：≤200ms
  - 内存占用：≤2GB

#### 4.1.2 重排模型
- **模型选择**：sentence-transformers/ms-marco-MiniLM-L-6-v2
- **功能要求**：
  - 对检索结果进行相关性重排
  - 支持query-document相关性打分
- **性能指标**：
  - 重排准确率：≥90%
  - 处理速度：≥500对文本/秒

#### 4.1.3 大语言模型
- **模型选择**：Qwen3:8b（通过Ollama本地部署）
- **功能要求**：
  - 支持中文理解和生成
  - 基于检索内容生成答案
  - 支持流式输出
  - 支持多轮对话
  - 降级模式（模型不可用时的友好提示）
- **性能指标**：
  - 答案相关性：≥90%
  - 回答准确性：≥85%
  - 响应时间：≤30秒（考虑LLM生成耗时）
  - 并发支持：≥10用户
  - 超时控制：120秒最大等待时间

### 4.2 数据需求

#### 4.2.1 数据来源
- **新闻数据源**：
  - 主流新闻媒体RSS源（人民网、新华网、央视新闻等）
  - 财经类专业媒体（财新、第一财经等）
  - 科技类媒体（36氪、虎嗅等）
  - 国际新闻源（BBC、CNN、Reuters等）

#### 4.2.2 数据规模
- **初始数据量**：≥10万条新闻记录
- **日增数据量**：≥1000条新闻记录
- **数据覆盖时间**：最近2年的新闻数据
- **向量库规模**：≥100万个向量

#### 4.2.3 数据质量要求
- **完整性**：新闻标题、正文、发布时间、来源必须完整
- **准确性**：内容真实可靠，来源可追溯
- **时效性**：新闻发布后24小时内入库
- **去重率**：≥95%的重复内容识别和去除

#### 4.2.4 数据标注
- **自动标注**：
  - 新闻分类（政治、经济、科技、体育等）
  - 关键词提取
  - 情感倾向分析
- **质量标注**：
  - 内容质量评分
  - 来源可信度评级
  - 时效性标记

### 4.3 算法边界与可解释性

#### 4.3.1 算法边界
- **检索范围限制**：仅基于已入库的新闻数据进行检索
- **时间边界**：优先展示近期新闻，超过1年的新闻降权处理
- **语言支持**：主要支持中文，英文支持有限
- **主题限制**：不涉及敏感政治话题的深度分析

#### 4.3.2 可解释性要求
- **检索结果溯源**：显示答案来源的具体新闻链接
- **相关度评分**：显示检索结果的相关度分数
- **置信度指示**：标明AI答案的置信度等级
- **多来源对比**：当存在不同观点时，展示多个来源的信息

### 4.4 评估标准

#### 4.4.1 检索效果评估
- **准确率**（Precision）：≥85%
- **召回率**（Recall）：≥80%
- **F1分数**：≥82%
- **用户满意度**：≥4.0/5.0

#### 4.4.2 生成质量评估
- **答案相关性**：≥90%
- **事实准确性**：≥95%
- **语言流畅度**：≥4.5/5.0
- **信息完整性**：≥85%

#### 4.4.3 系统性能评估
- **查询响应时间**：
  - 语义搜索：≤3秒
  - RAG问答：≤30秒
  - 向量检索：≤500ms
- **系统可用性**：≥99.5%
- **并发处理能力**：≥50用户同时在线
- **错误率**：≤1%
- **数据入库速度**：≥1000条/小时

### 4.5 伦理与合规

#### 4.5.1 数据合规
- **版权保护**：遵守新闻内容版权法规
- **隐私保护**：用户搜索数据加密存储
- **数据安全**：防止数据泄露和恶意访问
- **robots.txt遵守**：严格遵守网站爬取协议

#### 4.5.2 内容伦理
- **内容审核**：建立敏感内容过滤机制
- **偏见控制**：避免算法偏见和歧视性输出
- **虚假信息防范**：建立事实核查机制
- **价值观导向**：确保输出内容符合主流价值观

#### 4.5.3 用户伦理
- **透明度原则**：向用户说明AI系统的工作原理
- **用户控制**：允许用户控制个人数据使用
- **责任边界**：明确AI系统的能力边界和责任范围
- **错误纠正**：提供错误反馈和纠正机制

## 5. 非功能性需求

### 5.1 性能需求
- **响应时间**：
  - 语义搜索查询：≤3秒
  - RAG问答生成：≤30秒
  - 页面加载时间：≤2秒
  - 文件上传处理：≤60秒
  - 邮件发送：异步处理，不阻塞主流程
- **吞吐量**：
  - 支持并发用户数：≥50人
  - 每日查询处理量：≥10,000次
  - 数据采集速度：≥1000条/小时
  - 向量化处理：≥1000条文本/秒

### 5.2 安全需求
- **身份认证**：
  - JWT Token认证机制
  - Access Token有效期：24小时
  - Refresh Token有效期：7天
  - 密码bcrypt加密存储
- **数据加密**：
  - HTTPS传输加密
  - 敏感数据AES加密存储
  - 数据库连接加密
- **权限控制**：
  - 基于JWT的接口鉴权
  - 路由级别权限控制
- **安全防护**：
  - SQL注入防护
  - XSS攻击防护
  - CSRF防护
  - API限流和防刷
  - 邮件发送频率限制

### 5.3 可用性需求
- **系统可用性**：≥99.5%
- **故障恢复时间**：≤30分钟
- **数据备份**：每日自动备份，支持7天内数据恢复
- **监控告警**：实时监控系统状态，异常自动告警

### 5.4 扩展性需求
- **水平扩展**：支持服务器集群部署
- **数据库扩展**：支持读写分离和分库分表
- **模块化设计**：支持功能模块独立部署和升级
- **API兼容性**：向后兼容，支持版本迭代

### 5.5 易用性需求
- **界面设计**：符合现代Web设计标准，响应式布局
- **操作简便**：关键功能不超过3次点击到达
- **帮助文档**：提供完整的用户操作指南
- **错误提示**：友好的错误信息和操作建议
