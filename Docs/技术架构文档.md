## 2. 架构总览

### 2.1 系统架构概述

XU-News-AI-RAG系统采用分层架构设计，基于微服务理念构建，主要包括以下层次：

- **用户接入层**：负责用户请求的接入和响应
- **应用服务层**：处理业务逻辑和服务编排
- **AI模型层**：提供智能检索和生成能力
- **数据存储层**：管理结构化和非结构化数据
- **基础设施层**：提供计算、存储和网络资源

### 2.2 架构设计原则

#### 2.2.1 设计理念
- **分层解耦**：各层职责清晰，降低耦合度
- **服务化**：功能模块化，支持独立部署和扩展
- **数据驱动**：以数据为中心的架构设计
- **AI优先**：围绕AI能力构建系统架构

#### 2.2.2 技术原则
- **高可用性**：系统可用性≥99.5%
- **高性能**：关键接口响应时间≤3秒
- **可扩展性**：支持水平扩展和垂直扩展
- **安全性**：完善的安全防护机制
- **可维护性**：清晰的代码结构和监控体系

## 4. 关键技术架构

### 4.1 RAG(检索增强生成)架构

#### 4.1.1 RAG工作流程
```
用户查询 → 查询理解 → 向量检索 → 结果重排 → 上下文构建 → LLM生成 → 答案输出
    ↓         ↓         ↓         ↓         ↓         ↓         ↓
  Query    Embedding  FAISS     Rerank    Context   Qwen3     Response
Processing  Service   Search    Service   Builder   LLM       Formatter
```

#### 4.1.2 技术实现细节

**向量检索架构**
```python
class RAGPipeline:
    def __init__(self):
        # 嵌入模型
        self.embedding_model = SentenceTransformer('all-MiniLM-L6-v2')
        # 重排模型
        self.rerank_model = SentenceTransformer('ms-marco-MiniLM-L-6-v2') 
        # FAISS索引
        self.vector_index = faiss.IndexIVFFlat(
            quantizer=faiss.IndexFlatIP(384),
            dimension=384,
            nlist=1000
        )
        # LLM模型
        self.llm = Ollama(model="qwen3:8b")
    
    def search_and_generate(self, query: str) -> str:
        # 1. 查询向量化
        query_vector = self.embedding_model.encode(query)
        
        # 2. 向量检索 (召回Top-K)
        scores, indices = self.vector_index.search(
            query_vector.reshape(1, -1), k=20
        )
        
        # 3. 候选文档重排 (精排Top-N)
        candidates = self.get_documents_by_indices(indices[0])
        reranked_docs = self.rerank_model.rerank(query, candidates, top_k=5)
        
        # 4. 构建上下文
        context = self.build_context(reranked_docs)
        
        # 5. LLM生成答案
        prompt = self.build_prompt(query, context)
        response = self.llm.generate(prompt)
        
        return self.format_response(response, reranked_docs)
```

**上下文构建策略**
```python
def build_context(self, documents: List[Document]) -> str:
    """构建LLM输入上下文"""
    context_parts = []
    
    for i, doc in enumerate(documents):
        context_part = f"""
        来源{i+1}: {doc.source_name}
        时间: {doc.published_at}
        标题: {doc.title}
        内容: {doc.content[:500]}...
        链接: {doc.source_url}
        """
        context_parts.append(context_part)
    
    return "\n".join(context_parts)
```

### 4.3 向量化存储架构

#### 4.3.1 向量索引管理
```python
class VectorIndexManager:
    def __init__(self):
        self.dimension = 384
        self.index_factory = faiss.IndexFactory(
            self.dimension, 
            "IVF1000,Flat"
        )
        self.index = None
        self.id_mapping = {}
        
    def build_index(self, vectors: np.ndarray, knowledge_ids: List[int]):
        """构建向量索引"""
        # 训练聚类中心
        self.index.train(vectors)
        
        # 添加向量
        self.index.add(vectors)
        
        # 更新ID映射
        for i, kid in enumerate(knowledge_ids):
            self.id_mapping[i] = kid
            
        # 持久化索引
        self.save_index()
    
    def incremental_add(self, new_vectors: np.ndarray, new_ids: List[int]):
        """增量添加向量"""
        start_idx = len(self.id_mapping)
        
        # 添加新向量
        self.index.add(new_vectors)
        
        # 更新映射关系
        for i, kid in enumerate(new_ids):
            self.id_mapping[start_idx + i] = kid
            
        self.save_index()
    
    def search(self, query_vector: np.ndarray, top_k: int = 20) -> Tuple[np.ndarray, List[int]]:
        """向量相似度搜索"""
        scores, vector_indices = self.index.search(
            query_vector.reshape(1, -1), top_k
        )
        
        # 转换为知识库ID
        knowledge_ids = [self.id_mapping[idx] for idx in vector_indices[0]]
        
        return scores[0], knowledge_ids
```

#### 4.3.2 向量更新策略
```python
class VectorUpdateStrategy:
    def __init__(self):
        self.batch_size = 1000
        self.update_threshold = 100
        
    def should_rebuild_index(self, pending_updates: int) -> bool:
        """判断是否需要重建索引"""
        total_vectors = len(self.vector_manager.id_mapping)
        update_ratio = pending_updates / total_vectors
        
        # 更新比例超过10%时重建索引
        return update_ratio > 0.1
    
    def batch_update(self, new_documents: List[Document]):
        """批量更新向量"""
        # 向量化新文档
        vectors = self.embedding_model.encode([doc.content for doc in new_documents])
        knowledge_ids = [doc.id for doc in new_documents]
        
        if self.should_rebuild_index(len(new_documents)):
            # 重建完整索引
            self.rebuild_full_index()
        else:
            # 增量添加
            self.vector_manager.incremental_add(vectors, knowledge_ids)
```

```python
    def __init__(self):
        self.secret_key = os.environ.get('JWT_SECRET_KEY')

        # 访问令牌载荷
        access_payload = {
            'user_id': user_id,
            'token_type': 'access',
            'exp': datetime.utcnow() + self.access_token_expires,

            'user_id': user_id,
            'token_type': 'refresh',
            'exp': datetime.utcnow() + self.refresh_token_expires,
            'iat': datetime.utcnow(),
            'jti': str(uuid.uuid4())
        }
        
        access_token = jwt.encode(access_payload, self.secret_key, algorithm='HS256')
        refresh_token = jwt.encode(refresh_payload, self.secret_key, algorithm='HS256')
        
        # 将refresh token存储到Redis
        self.store_refresh_token(user_id, refresh_payload['jti'])

    def verify_token(self, token: str) -> Dict:

        try:
            payload = jwt.decode(token, self.secret_key, algorithms=['HS256'])
            
            # 检查令牌是否在黑名单中
```

```python
class MultiLevelCacheManager:
    def __init__(self):
        # L1缓存：本地内存缓存 (最快)
        self.l1_cache = TTLCache(maxsize=1000, ttl=300)  # 5分钟
        
        # L2缓存：Redis缓存 (快速)
        self.l2_cache = redis.Redis(
            host='localhost', port=6379, db=0,
            connection_pool=redis.ConnectionPool(max_connections=100)
        )
        
        # L3缓存：数据库查询缓存 (持久)
        self.l3_cache = DatabaseQueryCache()
    
    def get(self, key: str) -> Any:
        """多级缓存读取"""
        # L1缓存查找
        value = self.l1_cache.get(key)
        if value is not None:
            return value
            
        # L2缓存查找
        value = self.l2_cache.get(key)
        if value is not None:
            # 回填L1缓存
            self.l1_cache[key] = value
            return pickle.loads(value)
            
        # L3缓存查找
        value = self.l3_cache.get(key)
        if value is not None:
            # 回填L2和L1缓存
            self.l2_cache.setex(key, 3600, pickle.dumps(value))
            self.l1_cache[key] = value
            return value
            
        return None
    
    def set(self, key: str, value: Any, ttl: int = 3600):
        """多级缓存写入"""
        # 同时写入多级缓存
        self.l1_cache[key] = value
        self.l2_cache.setex(key, ttl, pickle.dumps(value))
        self.l3_cache.set(key, value, ttl)
```

```python
class OptimizedVectorSearch:
    def __init__(self):
        self.index = self.load_optimized_index()
        self.query_cache = LRUCache(maxsize=10000)
        
    def load_optimized_index(self):
        """加载优化的向量索引"""
        # 使用IVF+PQ压缩索引，平衡精度和速度
        quantizer = faiss.IndexFlatIP(384)
        index = faiss.IndexIVFPQ(
            quantizer, 384, 1000,  # nlist=1000个聚类中心
            64, 8  # 64个子向量，每个8位
        )
        
        # 设置搜索参数
        index.nprobe = 10  # 搜索10个聚类
        
        return index
    
    def search_with_cache(self, query_vector: np.ndarray, top_k: int = 20) -> List[SearchResult]:
        """带缓存的向量搜索"""
        # 生成查询缓存键
        query_hash = hashlib.md5(query_vector.tobytes()).hexdigest()
        cache_key = f"vector_search:{query_hash}:{top_k}"
        
        # 检查缓存
        cached_result = self.query_cache.get(cache_key)
        if cached_result:
            return cached_result
            
        # 执行向量搜索
        scores, indices = self.index.search(
            query_vector.reshape(1, -1).astype('float32'), 
            top_k
        )
        
        # 获取文档详情
        results = self.get_documents_by_indices(indices[0], scores[0])
        
        # 缓存结果
        self.query_cache[cache_key] = results
        
        return results
```

```python
            )
```

## 9. 技术选型说明

### 9.1 核心技术栈对比

| 技术领域 | 选择方案 | 备选方案 | 选择理由 | 风险评估 |
|---------|---------|---------|---------|---------|
| **前端框架** | Vue 3.x | React 18, Angular 14 | 学习成本低，生态成熟，开发效率高 | 生态相对较小 |
| **后端框架** | Flask 2.x | FastAPI, Django, Express | 轻量灵活，Python生态，易于集成AI | 性能相对较低 |
| **数据库** | SQLite + FAISS | PostgreSQL + Milvus | 部署简单，开发便捷，满足需求 | 扩展性有限 |
| **大语言模型** | Qwen3:8b | ChatGPT-4, Claude-3 | 开源免费，中文优秀，本地部署 | 性能依赖硬件 |
| **向量库** | FAISS | Milvus, Pinecone, Weaviate | 性能优秀，本地部署，成本可控 | 运维复杂度较高 |
| **缓存** | Redis | Memcached, Hazelcast | 功能丰富，生态完善，支持持久化 | 内存消耗较大 |
| **容器化** | Docker + Compose | Kubernetes, Podman | 简单易用，适合中小规模部署 | 集群管理能力有限 |
| **监控** | Prometheus + Grafana | DataDog, New Relic | 开源免费，功能强大，社区活跃 | 配置复杂度较高 |

### 9.2 关键技术决策

#### 9.2.1 数据库选择决策
**SQLite vs PostgreSQL**
```yaml
开发阶段选择SQLite:
  优势:
    - 零配置部署
    - 文件级别备份
    - 跨平台兼容性好
    - 适合单机部署
  劣势:
    - 并发能力有限
    - 不支持复杂查询优化
    - 扩展性受限

生产阶段可升级PostgreSQL:
  优势:
    - 高并发支持
    - 复杂查询优化
    - 丰富的扩展生态
    - 支持分布式部署
  迁移成本:
    - 中等（ORM抽象降低成本）
```

#### 9.2.2 向量库选择决策
**FAISS vs Milvus**
```yaml
FAISS优势:
  - 性能优秀（Facebook开源）
  - 本地部署无依赖
  - 内存占用可控
  - 支持多种索引类型

Milvus优势:
  - 分布式架构
  - 更好的运维界面
  - 自动索引优化
  - 企业级特性

选择FAISS原因:
  - 项目规模适中（<100万向量）
  - 本地部署要求
  - 降低运维复杂度
  - 成本控制需求
```

#### 9.2.3 AI模型选择决策
**Qwen3:8b vs 其他模型**
```yaml
Qwen3:8b优势:
  - 中文能力强
  - 8B参数平衡性能和资源
  - 支持本地部署
  - 阿里开源，持续维护

对比其他选择:
  - GPT-4: 性能最佳但成本高，需联网
  - Claude-3: 性能优秀但无本地版
  - ChatGLM: 中文能力强但生态较小
  - Baichuan: 性能一般，商业化程度高

最终决策因素:
  - 中文处理需求 (权重: 30%)
  - 本地部署要求 (权重: 25%)
  - 性能效果 (权重: 25%)
  - 成本控制 (权重: 20%)
```
